# Analytics & Promotion 遷移計畫 (已確認)

本計畫針對 **Analytics (`ms-identity-ga4.js`)** 與 **Promotion (`promotion.js`)** 兩個功能群進行詳細遷移規劃，嚴格遵守「不改 UI」、「完全註釋舊檔」、「新系統主動註冊」之原則。

## A) 現況盤點

### 1. Analytics (`js/ms-identity-ga4.js`)

*   **Public 行為**:
    *   在 `localStorage` 維護 `ms_user_uuid` (若無則生成)。
    *   向 `window.dataLayer` 推送 `ms_identity_ready` 事件 (含 User ID)。
*   **入口點**:
    *   **IIFE (立即執行)**: 腳本載入時立即執行。
*   **依賴**:
    *   `localStorage` (Keys: `ms_user_uuid`)
    *   `window.dataLayer` (GTM)
    *   `window.__MS_LOAD_BACKUP__` (Hook, 選配)
    *   `window.__MS_RESTORE_BACKUP__` (Hook, 選配)
*   **副作用**:
    *   **立即寫入**: 載入即檢查/寫入 `localStorage`。
    *   **立即推送**: 載入即推送 dataLayer。
*   **風險**:
    *   如果 Bridge 執行太晚，導致 GTM 載入時尚未有 dataLayer 資料，可能會漏掉首屏的 User ID 關聯。雖然目前是 defer，但 module script (React) 可能稍慢。

### 2. Promotion (`js/promotion.js`)

*   **Public 行為**:
    *   顯示/隱藏 AdSense 廣告 (`.ad-banner`)。
    *   提供 UI 控制按鈕狀態更新 (`updateAdEnabledButton`, `updateAdTestModeButton`)。
    *   管理廣告顯示頻率與時長。
*   **入口點**:
    *   `initAdSystem()` (由 `main.js` 呼叫)。
    *   `checkAndShowAd()` (定時器或手動呼叫)。
    *   Global Utils: `triggerAdManually`, `toggleAdEnabled`, `toggleAdTestMode`, `closeAdBanner`.
*   **依賴**:
    *   `localStorage` (Keys: `adConfig`, `adLastShown`, `adLastClosed`)
    *   `window.players`, `window.streamData` (判斷是否有內容以顯示廣告)
    *   DOM: `#ad-banner`, `#ad-enabled-btn`, `#ad-test-mode-btn` (直接操作 DOM ID)
    *   External: `window.adsbygoogle`
*   **副作用**:
    *   **Timers**: `setTimeout` (adTimer, adDisplayTimer) 持續運行。
    *   **DOM Manipulation**: 動態建立/移除 `div#ad-banner`。
*   **風險**:
    *   雙重 Timer: 若新舊系統同時運行，會導致廣告頻率加倍或閃爍。
    *   `main.js` 依賴: `main.js` 在 `DOMContentLoaded` 後 1 秒呼叫 `initAdSystem`。若 Bridge 未及時註冊 window API，`main.js` 的 `typeof` 檢查會失敗導致廣告不啟動 (雖然有 1s buffer，但需注意)。

## C) 唯一切換點與策略

### 切換點位置
*   **位置**: `src/bootstrap/legacyBridge.ts` (新增檔案)
*   **啟動**: 由 `src/main.tsx` 頂層 import 並執行。

### 實現方式
1.  **Analytics**:
    *   在 `legacyBridge.ts` 的 `setupBridge()` 中，直接呼叫 `analyticsInstance.init()`。
    *   這取代了舊檔 IIFE 的行為。
2.  **Promotion**:
    *   在 `legacyBridge.ts` 的 `setupBridge()` 中，將 `adManagerInstance` 的方法掛載回 `window`。
    *   ```typescript
        window.initAdSystem = () => adManagerInstance.init();
        window.toggleAdEnabled = () => adManagerInstance.toggleEnabled();
        // ... 掛載所有舊 public API
        ```
3.  **防止舊碼執行**:
    *   舊檔案 (`js/ms-identity-ga4.js`, `js/promotion.js`) 內容將被 `/* ... */` 包裹。
    *   因為舊檔被註釋，它們不會定義任何變數，也不會執行 IIFE。
4.  **解決載入順序風險**:
    *   `ms-identity-ga4.js` 原本是 IIFE (Immediate)。現在改由 `main.tsx` (Module) 啟動，時間點略晚但仍在 User Interaction 前，對 GTM 追蹤無實質影響。
    *   `promotion.js` 的 `initAdSystem` 是由 `main.js` 延遲 1 秒呼叫。這給了 React/Bridge 充裕的時間完成 `window.initAdSystem` 的註冊。只要 `main.tsx` 執行，API 就會就位。
